# Storage & Media Architecture

Trace handles thousands of screenshots generated by desktop agents. To manage this volume securely and cost-effectively, we leverage Cloudflare R2 object storage combined with a client-side expiry caching strategy.

## The Pre-Signed URL Strategy

All Cloudflare R2 buckets are kept strictly private. Neither the public internet nor standard authenticated users can access images directly via a static URL.

When a client needs to view an image, we use **Pre-Signed URLs**. 

### Why not proxy through Express?
If our Node.js server downloaded the image from R2 and streamed it to the client, it would consume massive amounts of CPU, RAM, and bandwidth. The Express server would quickly become a bottleneck.

### How Pre-Signed URLs solve this:
1. The client asks Express for an image.
2. Express verifies the user's `Tenant ID` matches the screenshot's metadata in the database.
3. Express generates a lightweight cryptographic string signature (valid for 1 hour) and returns a URL.
4. The client downloads the heavy image data directly from Cloudflare R2, bypassing the Node.js server entirely.

## Client-Side Expiry Caching (`expiresAt`)

Serving media via Pre-Signed URLs introduces a challenge: if an admin refreshes their dashboard, we don't want the frontend to bombard the backend with requests to generate new URLs for the same 50 images.

We solve this using the `expiresAt` caching pattern.

When the backend generates the signed URL, it explicitly returns the UTC timestamp of when that URL will die:
```json
{
  "url": "https://<accountId>.r2.cloudflarestorage.com/screenshots/...?X-Amz-Signature=...",
  "expiresAt": "2026-07-26T21:25:29.000Z"
}
```

The frontend caches this response in memory. Before rendering an image, the frontend checks if `Date.now()` is safely before the `expiresAt` timestamp. 
* If valid: It uses the cached URL instantly (Zero backend load).
* If expired: It silently fetches a fresh URL from the backend.

This ensures zero stale image bugs while drastically reducing database and S3 SDK calls.

## Image Compression (Sharp)

Before an image ever reaches Cloudflare R2, it undergoes compression. The desktop agent uploads raw Base64 strings. The backend worker decodes this and processes it using the `sharp` library to convert it into the highly efficient WebP format. This process typically reduces a 2MB screenshot down to ~80KB, saving massive amounts of storage space and significantly improving dashboard load times for administrators.
